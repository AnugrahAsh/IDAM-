## Running it

Requires Node.js `^20.19.0` or `>=22.12.0` (Vite 8's own requirement).

```bash
npm install
```

```bash
npm run dev
```

Then open **http://localhost:5181/iam/** — that exact URL. Vite is configured with
`base: '/iam/'` and `--strictPort`, so plain `/` will not serve the app. `/iam/` opens
straight on My Apps.

Production build: `npm run build` (outputs to `dist-idam/`).

Run `npm install` on the machine that will run the app. `node_modules/` holds
platform-specific native binaries (the bundler and the CSS engine), so a copy installed on one
operating system will not start on another. `node_modules/` and `dist-idam/` are both
regenerated by the commands above and are git-ignored.

Everything else — all 290 remaining files — is a **byte-identical copy** at its original path,
including the full route table in `data/nav.js`, `store/AppContext.jsx`, `main.jsx`,
`index.html`, `package.json`, `package-lock.json` and `vite.config.js`.

| File | Change | Why |
|------|--------|-----|
| `idam/src/App.jsx` | `PAGES` maps the nineteen routes above; the other `lazy()` imports and the `LoginPage` import are removed; while no session is signed in, the gate renders nothing and a short effect calls the console's own `signIn()` | those page files are not in this packet, so importing them would break the build. Every route not in `PAGES` already falls through to `PlaceholderPage` — that is the "work in progress" screen, unchanged console behaviour. The rest of the file — the role-based module gate (`moduleFor` / `can`), the notification greeting and the shell layout — is untouched |

## Sign-in

The sign-in screen is not in this packet. The session gate itself is unchanged
(`store/AppContext.jsx`); `App.jsx` signs a new session in on arrival, exactly as a completed
sign-in would:

- the console lands wherever the address bar points (My Apps for `/iam/`), so deep links work;
- the **Welcome back** notification popup opens, as it does after a real sign-in;
- **Log Out** (account menu) ends the session, shows its "Signed out" toast and starts a fresh
  session the same way;
- `/iam/login` lands on My Apps.

Dropping the sign-in page also drops `d3-geo`, `d3-timer` and the ~87 kB globe geometry
(`data/worldLand.js`). `package.json` is unchanged, so those packages still install; they are
simply unused.

## What the navigation does

The sidebar shows **every** section the full console has — Core, Groups, Applications,
Schedulers, Reports, Communications, Logging, System — with live badge counts driven from the
seed data (Approvals 22, Orphan Accounts 18, Segregation of Duties 8, Notification Center 6,
Background Jobs 5, Recertification 2). The command palette (`⌘K` / `Ctrl+K`) lists every route.

The nineteen built screens carry their full behaviour — registers, detail views, tabs, drawers,
wizards, manage views and sticky save bars. **Every other entry** opens that route's own title
over the "Screen in progress" card — for example *Groups*, *Applications*, *Segregation of
Duties*, *SSO Configurations*. Nothing errors, nothing dead-ends.

Each one lights up as its page joins a later packet: add the page files and one line to
`PAGES` in `App.jsx`.

Old addresses keep working — for example `/iam/passwordDictionary` opens the Dictionary tab of
Password Policy, and `/iam/settings/siem` opens the SIEM Transport tab of Security Events.

## Notes

**Data is fictional and in-memory.** Every screen reads static seed modules (`data/seed.js` and
each page's own data file), so every run starts from identical numbers. There is no backend:
edits, deletes and imports change React state and raise a toast. Some preferences and settings
persist in the browser's `localStorage` — theme, density, sidebar state, table columns and
saved views, notification read state, report pins, Settings values and the MFA policy — and the
signed-in flag lives in `sessionStorage`. Clearing the site data for `localhost:5181` returns
everything to the seed.

**Fonts.** The stylesheets ask for Inter and JetBrains Mono and fall back to the system UI and
monospace fonts when those are not installed. No font files are bundled — same as the main
project.

**Scripts.** `package.json` is identical to the main project's, so it still lists `deploy` and
`deploy:remote`. Those run the main project's deployment scripts, which are not part of this
packet; `dev`, `build` and `preview` are the ones that apply here.
